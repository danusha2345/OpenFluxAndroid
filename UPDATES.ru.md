# Обновления Android-приложения

При запуске приложение не чаще раза в сутки проверяет последний GitHub Release
`danusha2345/OpenFluxAndroid`. Если версия новее установленной, предлагает
скачать `OpenFluxAndroid.apk`. Перед открытием системного установщика оно
сверяет размер и SHA-256 с метаданными релиза, `applicationId`, `versionCode`
и сертификат подписи APK с установленным приложением. Android запрашивает у
пользователя разрешение на установку из этого источника и подтверждение
обновления; приложение не обходит этот запрос.

Для каждого релиза нужны:

1. Тег `v<versionName>`, например `v1.1.12`, и соответствующий `versionCode`
   по формуле `major*10000 + minor*100 + patch`.
2. APK с именем `OpenFluxAndroid.apk`, опубликованный в GitHub Release. GitHub
   должен отдавать для asset поле `digest: sha256:...`.
3. Подпись тем же сертификатом, что и предыдущая установленная версия.
   Копия текущего ключа хранится только локально, вне репозитория. Без неё
   выпускать обновление нельзя. Перед публикацией сравните SHA-256
   сертификата через `apksigner verify --print-certs` с предыдущим APK.
4. Сборка всех трёх ABI `libp1npplydtransport.so` из того же коммита
   OpenFlux, который указан в `app/src/main/openflux-version.txt`.

Локальная release-сборка читает `OPENFLUX_RELEASE_KEYSTORE` и
`OPENFLUX_RELEASE_PASSWORD` из окружения. Без них Gradle создаёт неподписанный
APK, который публиковать нельзя. Отладочный APK 1.1.11 и первый release APK
подписаны одним локальным сертификатом, поэтому возможна установка поверх
отладочной версии с сохранением данных. На устройстве это пока не проверено.
